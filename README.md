## 📌 1. Опис предметної області та функціонал

«Довідник Флориста» — це спеціалізований веб-сервіс для флористів, декораторів та клієнтів квіткових салонів, призначений для:
- **Каталогізації квітів:** сортові зрізані, кімнатні, екзотичні рослини та довговічні сухоцвіти.
- **Довідника з догляду (Care Guide):** професійні пам'ятки щодо частоти заміни води, оптимального температурного режиму, вимог до світла, вологості та секретів підрізання.
- **Підбору квітів до подій:** весілля, ювілеї, романтичні побачення, ділові протоколи тощо.
- **Комплексного пошуку та фільтрації:** фільтрація за категоріями, подіями, максимальною ціною, наявністю та текстовим запитом (за допомогою `Q`-об'єктів).
- **Списку обраного:** збереження улюблених квітів для авторизованих користувачів.
- **Форми консультації флориста:** замовлення авторського букета з перевіркою формату номера телефону та мінімального бюджету.
- **Адаптивного дизайну з перемикачем тем:** світло-рожева флористична гама з підтримкою контрастної темної теми (збереження вибору в cookies через Custom Middleware).

## 🚀 3. Швидкий старт та інструкція із запуску (В1.1, В1.3)

### Крок 1. Клонування репозиторію та перехід у каталог
```bash
git clone <URL_репозиторію>
cd zvit_python
```

### Крок 2. Створення та активація віртуального середовища
```bash
# macOS / Linux:
python3 -m venv venv
source venv/bin/activate

# Windows:
python -m venv venv
venv\Scripts\activate
```

### Крок 3. Встановлення залежностей із зафіксованими версіями (В1.1)
```bash
pip install -r requirements.txt
```

### Крок 4. Налаштування змінних оточення (В2.2)
Скопіюйте шаблонний файл `.env.example` у новий файл `.env`:
```bash
cp .env.example .env
```

Відкрийте файл `.env` та налаштуйте параметри:
```env
SECRET_KEY=your-django-super-secret-key-change-in-production
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost

# Налаштування СУБД MySQL (В2.1, В2.2)
DB_ENGINE=django.db.backends.mysql
DB_NAME=florist_db
DB_USER=root
DB_PASSWORD=your_mysql_password
DB_HOST=127.0.0.1
DB_PORT=3306
```

> **💡 Примітка щодо локального тестування:**  
> Якщо локальний сервер MySQL ще не запущений, застосунок дозволяє встановити `DB_ENGINE=django.db.backends.sqlite3` у файлі `.env` для швидкої демонстрації функціоналу.

### Крок 5. Створення бази даних у MySQL
Увійдіть у консоль MySQL клієнта та створіть базу:
```sql
CREATE DATABASE florist_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### Крок 6. Застосування міграцій та data-міграції (В3.3, В3.5)
```bash
python manage.py migrate
```
> Міграція автоматично застосує початкову схему та запустить **Data-міграцію (RunPython)** `0002_seed_initial_data`, яка автоматично наповнить базу тестовими категоріями, подіями, сортами квітів, довідниками з догляду, групами прав та користувачами!

### Крок 7. Запуск сервера розробки
```bash
python manage.py runserver
```
Відкрийте браузер за адресою: [http://127.0.0.1:8000/](http://127.0.0.1:8000/)

## 📋 6. Звіт про виконання обов'язкових та додаткових вимог практики

### 1. Проєкт і середовище
- **В1.1:** Проєкт `florist_project`, застосунок `catalog`, віртуальне середовище `venv`, `requirements.txt` із зафіксованими версіями.
- **В1.2:** Git-репозиторій з послідовною історією комітів за основними етапами розробки.
- **В1.3:** `README.md` із повною інструкцією запуску.
- **В1.4:** Маршрути налаштовано з `app_name = "catalog"`, у шаблонах та коді виключно `{% url %}` та `reverse()`.

### 2. База даних
- **В2.1:** **MySQL 8.0+** СУБД із підтримкою юнікоду `utf8mb4`.
- **В2.2:** Читання конфігурації з `.env` через `python-dotenv`. Файл `.env` додано до `.gitignore`, у репозиторії наявний `.env.example`.

### 3. Моделі
- **В3.1:** 5 моделей власного домену: `Category`, `Occasion`, `Flower`, `CareGuide`, `Favorite`. Поле власника `owner = ForeignKey(User)`.
- **В3.2:** Різні типи полів: `CharField`, `TextField`, `DecimalField`, `PositiveIntegerField`, `DateTimeField`, `DateField`, `BooleanField`, `choices` (`DIFFICULTY_CHOICES`, `LIGHT_CHOICES`, `SEASON_CHOICES`), метод `__str__()` у кожній моделі.

- **В3.4:** Всі моделі зареєстровані в `admin.py` із конфігураціями `ModelAdmin` (`list_display`, `list_filter`, `search_fields`, `list_editable`, `prepopulated_fields`).
- **В3.5:** Повноцінний набір тестових квітів із реальними фотографіями, описами та порадами догляду.

### 4. Шаблони і статика
- **В4.1:** Базовий шаблон `base.html` (`{% extends %}`, `{% block %}`), повторювані фрагменти винесено в `templates/catalog/includes/` (`navbar.html`, `footer.html`, `messages.html`, `flower_card.html`).
- **В4.2:** Підключення статики `{% load static %}`, фреймворк Bootstrap 5, авторський CSS-файл `florist.css` із підтримкою світлої/темної теми.
- **В4.3:** Власні DTL-теги у `catalog/templatetags/florist_tags.py`:

  - `is_in_favorites` (simple_tag) — перевірка збереження квітки;
  - `render_flower_card` (inclusion_tag) — інкапсульований рендеринг картки рослини.

- **В5.1:** `FlowerForm` та `CareGuideForm` на основі `ModelForm`, поля перелічені явно (без `__all__`), поле `owner` виключено з форми.

- **В6.5:** Маршрути з конвертерами `<int:pk>` та `<slug:slug>`.

### 7. Користувачі, ролі і доступ
- **В7.1:** Реєстрація через `UserRegistrationForm`, вхід `CustomLoginView`, вихід виключно через POST-запит (`LogoutView`).
- **В7.2:** Власник `owner` автоматично присвоюється у `form_valid()`.
- **В7.3:** Доступ до створення, редагування та видалення лише для автентифікованих (`LoginRequiredMixin`); заборона зміни чужих записів (`OwnerOrStaffRequiredMixin`).
- **В7.4 & В7.5:** Ролі «Клієнт» та «Флорист». Спеціальний аналітичний розділ `/florist-dashboard/` та створення довідників догляду дозволено лише ролі флориста; перевірка здійснюється на стороні сервера (`UserPassesTestMixin`, `PermissionRequiredMixin`).

### 8. Безпека
- **В8.1:** Жодної конкатенації в SQL; використання параметризованого Django ORM.
- **В8.2:** Виведення даних без сирих `|safe` / `mark_safe` для користувацького вводу.

### Додаткові вимоги (Д1 - Д7)
- **Д1:** `ManyToManyField(Occasion, related_name='flowers')`.
- **Д2:** Обґрунтовані типи видалення `on_delete`:
  - `Category`: `PROTECT` (захист каталогу від випадкової втрати зв'язаних сортів);
  - `owner`: `CASCADE` (каскадне видалення записів разом із користувачем);
  - `flower`: `CASCADE` у `CareGuide` (пам'ятка не має сенсу без квітки);
  - `expert`: `SET_NULL` у `CareGuide` (збереження корисної інструкції при видаленні акаунта автора).
- **Д3:** `Meta`: `ordering`, `verbose_name`, `verbose_name_plural`, `UniqueConstraint` на збереження в обране.
- **Д4:** Пошук за допомогою `Q`-об'єктів, статистика за допомогою `annotate(Count())` та `aggregate(Avg(), Min(), Max())`.
- **Д5:** Запобігання проблемі N+1 запитів завдяки `select_related('category', 'owner')` та `prefetch_related('occasions')`; підключено `django-debug-toolbar`.
- **Д6:** Власні права `can_publish_catalog`, `can_manage_care_guide` у `Meta.permissions`, розподіл прав через `Group`.
- **Д7:** Власний middleware `ThemeAndTimingMiddleware` (керування темою оформлення та заголовок часу `X-Response-Time-ms`); маршрути зміни пароля.
